# Drift detection rules

How `prj-update-docs` decides whether a doc page is in sync with its source artifact.

## Inputs

| Source                                | Doc page                              |
| ------------------------------------- | ------------------------------------- |
| `skills/<name>/SKILL.md` + `references/*.md` | `docs/reference/skill-<name>.md`      |
| `agents/<role>.md`                    | `docs/reference/agents/<role>.md`     |
| `hooks/hooks.json` (one entry)        | one section in `docs/reference/config/hooks.md` |
| `bin/<script>`                        | `docs/reference/config/bin-<script>.md` |
| `.mcp.json` (one server)              | `docs/reference/config/mcp-<server>.md` |
| `monitors/monitors.json` (one entry)  | `docs/reference/config/monitor-<name>.md` |

## Drift-manifest

Persisted at `.temp/prj-update-docs/state/drift-manifest.json`. Schema:

```json5
{
  version: 1,
  artifacts: {
    "skills/plan-brainstorm": {
      sources: [
        { path: "skills/plan-brainstorm/SKILL.md", sha256: "<hash>" },
        { path: "skills/plan-brainstorm/references/persona.md", sha256: "<hash>" }
      ],
      doc: { path: "docs/reference/skill-adk-plan-brainstorm.md", sha256: "<hash>" },
      lastSyncedAt: "2026-04-22T16:30:00Z"
    }
    // ...
  }
}
```

## Decision matrix

| Source state           | Doc state           | Action                                                                                |
| ---------------------- | ------------------- | ------------------------------------------------------------------------------------- |
| present, hash unchanged | present, hash unchanged | Skip.                                                                            |
| present, hash changed   | present              | Regenerate the page from `page-template.md`. Update manifest.                       |
| present, hash unchanged | present, hash changed (manual edit) | Surface in report under "Manual edits". Re-generate only with `--mode fix`. |
| present, new            | absent               | Generate the page. Update manifest. Add to section `meta.json5` items list.         |
| absent (deleted)        | present              | Propose deletion in report. Delete only with `--mode fix` + explicit confirmation.  |
| renamed                 | present (old name)   | Generate page at new name. Propose deletion of old page. Surface rename in report.  |

## Hashing rules

- SHA-256 of file bytes (no normalisation) — exactly matches
  `node_modules/diagramkit/`'s manifest hashing convention so re-runs across
  diagramkit and prj-update-docs stay consistent.
- For multi-file artifacts (skill + its `references/*`), the artifact hash is the SHA-256
  of the concatenation `path1\n<hash1>\npath2\n<hash2>\n...` (sorted by path).

## Manual-edit detection

Compare:

1. The doc page's current SHA-256.
2. The SHA-256 stored in the manifest from the previous run.

If they differ but the source is unchanged, a human (or another agent) edited the page
directly. Behaviour:

- `--mode review`: surface in report; no writes.
- `--mode auto` (default): surface in report and **preserve** the manual edit. Re-generation
  requires `--mode fix` to overwrite.
- `--mode fix`: overwrite, but include the diff in the report so the user can re-apply
  any genuine improvements.

## Behavioural drift (prose vs source)

In addition to hash drift, run a structural diff:

| Check                                                     | Severity         |
| --------------------------------------------------------- | ---------------- |
| Doc references a section header that no longer exists in source | error      |
| Doc lists an input (`<arg>`) that doesn't appear in source       | error      |
| Doc shows a CLI invocation that fails `--dry-run`               | error      |
| Doc cross-links a skill / agent that no longer exists           | error      |
| Doc cross-links a skill that exists but has been renamed         | warn      |
| Doc references a `node_modules/...` path that doesn't exist     | warn      |
| Doc has TODO / FIXME / "TBD" markers                            | info      |

Errors block the page from being marked "in sync"; the run continues to the next page,
but the final report must list every error.

## Ignored files

Anything matched by the inventory rules' "Always ignore" list. In addition:

- `docs/reference/skills/` (placeholder index folder; not regenerated by this skill).
- `docs/concepts/`, `docs/guide/` (curated by humans; only flagged when their internal
  cross-links break).

## Ignore pragma

A page can opt out of automated regeneration with frontmatter:

```yaml
---
title: '...'
prj_update_docs: skip
---
```

This is the only sanctioned way to keep a hand-written page that this skill must not
touch. Surfaced in the report under "Skipped (opt-out)".

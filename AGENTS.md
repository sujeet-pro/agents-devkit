# ADK Repository Guidance

Canonical entry point for any agent working **on** this repository (`agents-devkit` itself, not the ADK skills installed elsewhere). `CLAUDE.md` and `GEMINI.md` are thin runtime-specific deltas that point back here.

## What this repo is

**This repo IS the `adk` Claude Code plugin.** A single `.claude-plugin/plugin.json` at the root makes the entire repo loadable via `claude --plugin-dir <path>` or installable from a marketplace. There is no separate "installer" — the Claude plugin host loads everything.

For non-Claude agents (Cursor, Codex, Gemini, Antigravity, generic) and for the third-party `npx skills` loader, a parallel `agents-skills/adk-<name>` tree of folder-level symlinks exposes the same skills under `adk-<name>` names.

## Directory map

| Path | Purpose | Notes |
| --- | --- | --- |
| [.claude-plugin/](./.claude-plugin/) | Plugin manifest + private marketplace entry | `plugin.json` (name `adk`), `marketplace.json` |
| [skills/](./skills/) | All skills, bare names, no `adk-` prefix | Each is `skills/<name>/SKILL.md` + `references/` |
| [agents/](./agents/) | Claude subagents | One file per role; `name`, `description`, `model`, `tools`, `skills` frontmatter |
| [hooks/](./hooks/) | `hooks.json` — Claude plugin hook config | Pre/Post tool, Stop, SessionStart |
| [.mcp.json](./.mcp.json) | Bundled MCP server registry | `${ENV_VAR}` placeholders; resolved by `bin/adk-mcp-install` from `~/.zshenv` |
| [monitors/](./monitors/) | `monitors.json` — background watchers | e.g., `gh pr checks --watch` for `cicd-monitor` |
| [settings.json](./settings.json) | Plugin-level Claude defaults | `subagentStatusLine` etc. |
| [bin/](./bin/) | CLI scripts (in `PATH` when plugin enabled) | `canonical/` + 6 scripts; see below |
| [agents-skills/](./agents-skills/) | Folder-level symlinks `adk-<name> -> ../skills/<name>` | For `npx skills add` and non-Claude agents |
| [skills-manifest.json](./skills-manifest.json) | Auto-generated by `bin/adk-validate` | For `npx skills` compat |
| [docs/](./docs/), [gh-pages/](./gh-pages/) | Pagesmith docs source + built site | UNTOUCHED in current restructure |

There is no `cli/`, no `agents-cursor/`, no `agents-codex/`, no `mcp-config/`, no `global-prompts/`, no `workflows/`. Everything that used to live in those folders now lives where the Claude plugin spec expects it.

## Skill folder shape

```
skills/<name>/
  SKILL.md
  references/
    how-it-works.md            # required: mermaid diagram + decision flow
    modes.md                   # required: which --mode this skill supports
    persona.md / workflow.md / clarifying-questions.md / output-format.md /
    artifact-format.md / validator.md / anti-patterns.md / examples.md
    interaction-contract.md    # PHYSICAL COPY synced from bin/canonical/
    [optional: research-protocol.md, mcp-fallback.md, multi-repo.md, scripts/]
```

Migrated skills keep their existing `<task>-prefixed` reference filenames (e.g. `plan-brainstorm-persona.md`) to minimize churn. New skills use bare names.

## SKILL.md frontmatter

```yaml
---
name: <skill-name>            # required, must equal folder basename
description: |                # required, single paragraph; Claude uses it for auto-invoke
  <when to use, what it does, when NOT to use>
metadata:                     # optional, ADK-specific
  category: meta | discovery | plan | frontend | build | review | docs | audit | publish | observability | bootstrap
  kind: top | router | task
  modes: [auto, fix, review]
  layer: 0..10
  needs_mcp: [github, datadog, ...]
disable-model-invocation: false
---
```

## Cross-reference convention

When a `SKILL.md` references another skill, use **both** forms on first mention:

> Hand off to `@adk:plan-spec` (a.k.a. `adk-plan-spec`).

When referencing a subagent: `agents/<role>.md` (no prefix).

The validator (`bin/adk-validate`) enforces dual-form on first mention.

## Working artifacts (`.temp/`)

All intermediate output goes under `.temp/` (gitignored). The canonical layout enforced by `temp-folder` skill:

```
.temp/task-<slug>/
  context.md, requirements.md, scope.md, brainstorm.md, spec.md, design.md, roadmap.md
  preview/sample-{1..5}.html
  plan.md
  validation/<phase>.md
  browser-validation/<mode>/...
  report.md
```

Also at top-level:

| Path | Purpose |
| --- | --- |
| `.temp/plans/<slug>.md` | Restructure / refactor plans (no specific task) |
| `.temp/drafts/<slug>.md` | Prose drafts before promotion |
| `.temp/reports/<slug>.md` | Reviews, audits, investigations |
| `.temp/reference-repos/<owner>__<repo>/` | Cloned external repos for research |
| `.temp/notes/<slug>.md` | Short-lived working notes |

## Interaction model

Every skill is **highly interactive by default** and supports `--auto` for unattended runs. The full contract lives at `bin/canonical/interaction-contract.md` and is propagated byte-identically into every skill's `references/interaction-contract.md`.

Many skills also support `--mode review | fix | auto` — see `skills/mode-contract/SKILL.md`.

## Maintenance commands

```bash
npm run validate              # bin/adk-validate — structural + content checks
npm run validate:sync         # bin/adk-sync-contracts --check
npm run sync-contracts        # bin/adk-sync-contracts (propagate canonical files)
npm run skills:manifest       # regenerate skills-manifest.json
npm run install:local         # bin/adk-install (symlink for non-Claude agents)
npm run install:mcp           # bin/adk-mcp-install (MCP servers from .mcp.json + ~/.zshenv)
npm run doctor                # bin/adk-doctor
npm run docs:build            # build gh-pages/ from docs/
```

## Install paths (for end users)

1. **Claude Code plugin (primary):** `claude --plugin-dir ./agents-devkit` for dev, or install from the marketplace at `.claude-plugin/marketplace.json` once the user adds it.
2. **`npx skills add sujeet-pro/agents-devkit`:** picks up the `agents-skills/` tree (folder-symlinks named `adk-<name>`).
3. **Local symlink for multi-agent:** `bin/adk-install` symlinks the `agents-skills/adk-<name>` folders into `~/.cursor/skills/`, `~/.codex/skills/`, `~/.agents/skills/`, etc. (macOS only).

## Core rules for editors of this repo

- Plan before non-trivial change; lock plan in `.temp/plans/`.
- Write intermediate artifacts to `.temp/` only; never the repo root.
- Validate every change with `npm run validate`.
- Keep output concise and bullet-first.
- Do not present inference as fact.
- Do not edit `references/interaction-contract.md` in any skill — edit `bin/canonical/interaction-contract.md` and run `npm run sync-contracts`.
- Use `gh` CLI for all GitHub operations (PRs, issues, runs, releases). MCP is fallback.
- Do NOT touch `docs/` or `gh-pages/` in the current restructure (per user).

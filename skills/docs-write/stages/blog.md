# Stage: Blog Post

This stage covers blog posts, release notes, and technical announcements. It owns both first drafts and direct revisions.

## Type-Specific Phase Guidance

### Exploration
- Research the topic, gather supporting data, benchmarks, and examples
- Identify the target audience and their technical level
- Review existing blog posts for tone, style, and formatting conventions
- If this is a release announcement, scan git history for notable changes

### Brainstorm
- Present 2-3 angle/framing options for the post
- Discuss tone: conversational, formal, tutorial-style, announcement-style
- Determine the key takeaway the reader should leave with

### Execute
- Write the post following the document structure below
- Maintain a consistent voice throughout
- Optimize for readability: short paragraphs, clear headings, visual breaks

## Document Structure

### Title
Concise, descriptive, and engaging. Avoid clickbait.

### Introduction
- Hook: a compelling opening that frames the problem or opportunity
- Context: why this matters to the reader right now
- Preview: what the reader will learn or gain

### Body Sections
Structured by logical flow. Each section should:
- Make one clear point
- Include code examples, diagrams, or data where they add value
- Transition smoothly to the next section

### Key Takeaways
- Bullet list of the most important points
- Actionable next steps for the reader

### Conclusion
- Recap the main message
- Call to action (try it, read more, provide feedback)

### Metadata
- Author, date, tags/categories
- Related posts or documentation links

## Writing Rules

- Write for humans, not search engines. Clarity and value come first.
- Use active voice and concrete examples.
- Code examples must be tested and runnable where possible.
- Keep paragraphs short (3-5 sentences).
- Include visuals when they aid understanding.

## Type-Specific Output Format

Markdown file suitable for the team's blog platform. Include frontmatter if the platform uses it (Hugo, Jekyll, etc.).

## Validation Checklist

- Title is clear and descriptive
- Introduction hooks the reader and sets expectations
- All code examples are correct and tested
- Tone is consistent throughout
- Key takeaways are actionable
- No broken links or missing references

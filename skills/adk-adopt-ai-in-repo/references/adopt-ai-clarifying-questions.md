# Clarifying Questions for `adk-adopt-ai-in-repo` (default-ask mode)

When running without `--auto`, the skill asks these questions in order, one at a time, and waits for an answer before moving on.

Under `--auto`, the skill picks the option marked `(default)` in each question without asking, and lists every choice it auto-picked in the final report.

### Question 1

**Q:** What is the target repo path?

**How to pick:** Default `(default)` = the current working directory. Override only if you are scaffolding a sibling repo from another working directory.

### Question 2

**Q:** Fresh bootstrap or `--refresh` an existing setup?

**How to pick:**

- The skill auto-detects from the presence of `ai-guidelines/`, `<!-- adk:adopt:start -->` markers in `AGENTS.md` / `CLAUDE.md`, and existing `.claude/skills/*` / `.cursor/skills/*`.
- `fresh-bootstrap` `(default when no scaffolding present)` — generate the full tree.
- `--refresh` `(default when scaffolding present)` — update managed sections; preserve user-authored content per `adopt-ai-merge-strategy.md`.

### Question 3

**Q:** Wire hooks (`.cursor/hooks.json`, `.claude/settings.json`) or skip with `--no-hooks`?

**How to pick:**

- `wire-hooks` `(default)` — adds pre-commit (lint+format) and pre-push (typecheck+test) hooks calling `ai-guidelines/scripts/run_project_checks.py`. Real repo-native commands.
- `--no-hooks` — skip hook configs but still document the recommended hook commands in `ai-guidelines/scripts-and-commands.md`. Use when the repo already has husky / lefthook / pre-commit and you do not want to disturb it.

### Question 4

**Q:** Scope: all detected stacks or a single one?

**How to pick:**

- `all` `(default)` — generate guidance for every detected stack. Standard for single-stack repos and most monorepos.
- `--scope <stack>` (e.g., `frontend`, `backend`, `data`) — narrow to one slice. Use when the repo is a large monorepo and you only own one slice.

### Question 5 (refresh mode only)

**Q:** Merge aggressiveness for existing user-authored files?

**How to pick:**

- `preserve-and-merge` `(default)` — only update managed sections (between `<!-- adk:adopt:start --> ... <!-- adk:adopt:end -->` markers); leave everything else as-is. Surfaces a merge diff for review.
- `replace-managed-only` — overwrite ONLY files that were generated by a previous run of this skill (detected via marker presence). User-authored files not touched at all.
- `report-conflicts-only` — produce a merge plan but do NOT write anything. Useful when many files exist and you want to inspect before committing.

### Question 6

**Q:** Commit the generated tree, or leave it staged for the user to review?

**How to pick:**

- `leave-unstaged` `(default)` — write the files; leave them unstaged so the user can `git diff` and pick what to commit.
- `stage-all` — `git add` the generated tree (still does not commit). Use when running `--auto` in CI-style.
- `commit-with-message` — `git commit` with a generated message. Use only with explicit user approval; never default.

## Standard option-presentation shape

Where the answer is multiple-choice, present each option as:

```
### Option <A | B | C>: <short label>
- What it does: <one sentence>
- Pros: <2-3 bullets>
- Cons: <2-3 bullets>
- Best when: <one sentence with a concrete signal>
- Blast radius: surgical | bounded | transformative
- Reversibility: easy | moderate | hard
```

Mark exactly one option `(default)` and say in one sentence why it is the safest pick for the current evidence.

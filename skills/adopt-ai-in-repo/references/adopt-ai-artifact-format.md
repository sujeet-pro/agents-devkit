# Artifact Format for `adk-adopt-ai-in-repo`

The deliverable is a tree of files under the TARGET repo (not under `.temp/`). Working notes (evidence summary, validator log, merge diffs) live under `.temp/`.

## Artifact type

`ai-scaffolding` — a multi-file output composed of:

- `ai-guidelines/` — canonical knowledge tree (per `adopt-ai-output-blueprint.md`)
- root `AGENTS.md` — neutral cross-agent router
- root `CLAUDE.md` — Claude-specific delta
- `.claude/skills/<name>/SKILL.md` — thin Claude skill wrappers (default 7 wrappers)
- `.cursor/skills/<name>/SKILL.md` — thin Cursor skill wrappers (default 7 wrappers)
- `.cursor/rules/project-ai-guidelines.mdc` — Cursor rule pointing at `ai-guidelines/`
- `.cursor/hooks.json` — Cursor hooks (when `wire-hooks`)
- `.claude/settings.json` — Claude hook config (when `wire-hooks`)
- `ai-guidelines/scripts/refresh_ai_guidelines.py` + `run_project_checks.py` — Python maintenance helpers

## Format per piece

| Piece | Format | Required shape |
| --- | --- | --- |
| `ai-guidelines/*.md` | Markdown | Per `adopt-ai-output-blueprint.md` section content |
| `AGENTS.md` | Markdown | Neutral; thin pointer to `ai-guidelines/README.md`; `<!-- adk:adopt:start --> ... <!-- adk:adopt:end -->` markers wrap managed sections |
| `CLAUDE.md` | Markdown | Claude-specific delta only; thin pointer to `ai-guidelines/README.md` + skill discovery notes |
| Skill wrappers | Markdown + YAML frontmatter | 10-30 lines; per `adopt-ai-skill-wrapper-pattern.md` |
| Cursor rule (`.mdc`) | MDC frontmatter + Markdown | Per Cursor rule conventions |
| `.cursor/hooks.json` | JSON | Per Cursor hook schema |
| `.claude/settings.json` | JSON | Per Claude hook schema |
| Python helpers | `.py` | PEP 8; argparse-driven CLI; cross-platform (no shell-specific calls) |

## Path / Location

| Artifact | Location |
| --- | --- |
| Generated file tree | IN the target repo (per `adopt-ai-output-blueprint.md`) |
| Evidence summary | `.temp/notes/adopt-ai-<repo-slug>-evidence.md` |
| Validator log | `.temp/notes/adopt-ai-<repo-slug>-validator.md` |
| Merge diff (per touched file) | `.temp/notes/adopt-ai-<repo-slug>-merge-diff.md` |
| Final report | `.temp/reports/adopt-ai-<repo-slug>.md` |
| Plan (pre-approval) | `.temp/plans/adopt-ai-<repo-slug>.md` |

`<repo-slug>` = the basename of the target repo's root directory, kebab-cased.

## .temp/ contract

All intermediate artifacts (evidence summary, validator log, merge diffs, plans, drafts) MUST be written under `.temp/` in the host repo (i.e., the repo where the agent is running, not necessarily the target repo if they differ), using these subfolders:

| Path | Purpose |
| --- | --- |
| `.temp/plans/<slug>.md` | Implementation, refactor, or migration plans |
| `.temp/drafts/<slug>.md` | Prose drafts before promotion |
| `.temp/reports/<slug>.md` | Reviews, audits, investigations, final reports |
| `.temp/notes/<slug>.md` | Short-lived working notes (validator log, evidence summary, merge diff) |
| `.temp/reference-repos/<owner>__<repo>/` | Cloned external repos for research |

`.temp/` is gitignored. Promote a file out of `.temp/` ONLY when it is the deliverable the user asked for, in the location they asked for it. For this skill, the only "promotion" is the IN-REPO files (which write to the target repo, not to `.temp/`).

## Promotion rule

For `adk-adopt-ai-in-repo`, the in-repo file tree IS the deliverable; it is written directly to the target repo (not to `.temp/`). The `.temp/notes/` and `.temp/reports/` files stay in `.temp/` — they are for the user's audit / replay.

## Idempotency

- Re-running this skill on the same repo with `--refresh` must NOT churn unchanged files. Detect "unchanged" by content hash, not by mtime.
- Files generated by a previous run are detected via `<!-- adk:adopt:start -->` markers; user-authored files lack those markers.
- The validator's Phase 4 records per-file outcome (NEW / UPDATED / SKIPPED-NO-CHANGE / SKIPPED-USER-CONTENT) in the validator log.

## Markers

Every generated file (Markdown + JSON) carries opening/closing markers around the managed section:

```
<!-- adk:adopt:start -->
... managed content ...
<!-- adk:adopt:end -->
```

JSON files use a `// adk:adopt:start` / `// adk:adopt:end` pair in JSON5 OR an `_adk_adopt` key with the marker version. Without markers, the merge strategy treats the file as user-authored.

# Document Guidelines

Guidelines for writing and reviewing different types of documents. Load the relevant type-specific guideline alongside `general.md` for any document review.

## Index

### General

- [general.md](./general.md) -- Baseline language, grammar, structure, and formatting rules. Always loaded alongside type-specific guidelines.
- [research-and-fact-checking.md](./research-and-fact-checking.md) -- Research workflow, source priority hierarchy, fact-checking rules, version evolution requirements. Loaded for research-driven content (articles, blog posts, project docs).

### Document Types

- [appraisal-review.md](./appraisal-review.md) -- Performance review documents. Impact-quantified accomplishments, SMART goals, development plans.
- [article.md](./article.md) -- Deep-dive technical articles. Principal engineer voice, spec-referenced, exhaustive edge cases, benchmark-backed.
- [blog.md](./blog.md) -- Blog posts. Opinion-driven, scannable, conversational, with practical takeaways.
- [coding-guidelines-doc.md](./coding-guidelines-doc.md) -- Coding guidelines documents. Standards and conventions for a codebase or team.
- [community-guidelines.md](./community-guidelines.md) -- Community guidelines documents. Behavioral expectations and moderation policies.
- [erd.md](./erd.md) -- Engineering Requirements Documents. Technical requirements derived from product needs.
- [feedback.md](./feedback.md) -- Feedback documents. SBI model, behavior-focused observations, actionable suggestions.
- [hld.md](./hld.md) -- High Level Design documents. System architecture for stakeholders and cross-team engineers.
- [lld.md](./lld.md) -- Low Level Design documents. Implementation-level detail for a single component or feature.
- [prd.md](./prd.md) -- Product Requirements Documents. What a product should do, with success criteria.
- [project.md](./project.md) -- Project documentation. Architecture diagrams, tested quick starts, configuration and deployment guides.
- [tdd.md](./tdd.md) -- Technical Design Documents. Engineering approach with trade-off analysis.
- [tool-evaluation.md](./tool-evaluation.md) -- Tool evaluation documents. Structured comparison and recommendation for tool selection.
- [incident-report.md](./incident-report.md) -- Incident postmortem / report documents. Blameless root-cause analysis with action items.
- [status-report.md](./status-report.md) -- Sprint / weekly status reports. Progress tracking with metrics and blockers.
- [release-notes.md](./release-notes.md) -- Release notes / changelog documents. User-facing change summaries.
- [api-reference.md](./api-reference.md) -- API reference documentation. Endpoint specifications with examples.
- [onboarding.md](./onboarding.md) -- Onboarding / getting started guides. New hire setup and orientation.

### Coding Guidelines

For code-related guidelines (language-specific standards, architecture, security, testing), invoke `/coding` which detects the repo stack and loads the appropriate coding guidelines automatically.

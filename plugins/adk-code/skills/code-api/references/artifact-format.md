# `code-api` — artifact format

## `.temp/task-<slug>/` layout

```
.temp/task-<slug>/
├── prompt.txt                                 # verbatim user prompt + ISO timestamp
├── use-cases.md                               # Phase 2 — top 3 use cases
├── candidates.md                              # Phase 3 — 2-3 candidate contracts
├── design.md                                  # Phase 4 — picked + rationale + Hyrum's Law caveats
├── contract.<ext>                             # Phase 5 — concrete artifact (OR in working tree)
├── deprecation-plan.md                        # Phase 6 — if --breaking
├── (optional) skill-plan.md                   # if called from /adk-core:auto
└── report.md                                  # Phase 7 — final report
```

The `contract.<ext>` may live in:

- **Working tree** at the repo's documented contract location (e.g. `openapi.yaml`, `proto/foo.proto`, `src/index.ts`). Preferred when the location exists.
- **`.temp/task-<slug>/contract.<ext>`** when no such location exists yet. The report recommends where to land it.

## Slug rules

1. Kebab-case. Often shaped `api-<scope>-<noun>` (e.g. `api-orders-v2`, `api-checkout-sdk-v1`, `api-cli-migrate`).
2. 3-6 words.
3. Date-prefix only for disambiguation.
4. Generated by `bin/adk-task-slug`.

## Required artifacts (cannot skip even under `--auto`)

- **`use-cases.md`** with at least 1 use case (3 recommended).
- **`candidates.md`** with at least 2 candidates.
- **`design.md`** with the picked candidate, rationale, and Hyrum's Law caveats.
- **A concrete contract artifact** (`.temp/task-<slug>/contract.<ext>` or working tree).
- **`deprecation-plan.md`** if `--breaking` set (or if the design implies breaking changes).

## Contract artifact extensions by type

| Type | Extension | Where it lives |
| --- | --- | --- |
| REST | `.yaml` (OpenAPI) | repo's `openapi.yaml` (or `swagger.json`) |
| RPC (gRPC / Twirp) | `.proto` | repo's `proto/` directory |
| GraphQL | `.graphql` | repo's `schema.graphql` |
| SDK / module (TS) | `.ts` / `.d.ts` | repo's `src/index.ts` + `package.json` `"exports"` |
| SDK / module (Python) | `.py` (with type hints) + `__init__.py` exports | repo's `__init__.py` |
| CLI | `usage.txt` or commander spec | repo's `src/commands/<cmd>.ts` |
| Types-only (shared) | `.ts` / `.d.ts` | repo's shared types module |

## Cross-skill compatibility

- When `code-api` is followed by `/adk-code:code-write` (implement behind the contract), the implementation reads `design.md` + the contract artifact as inputs.
- When `code-api` is followed by `/adk-docs:docs-write` (usage docs), the docs skill reads `design.md` + the contract artifact.
- When `code-api` is followed by `/adk-docs:docs-publish-confluence` (RFC publication), the docs publishing reads `design.md`.
- When `code-api` is followed by `/adk-review:review-code-changes`, the review skill reads `report.md` + `design.md` + the contract artifact.

## Hyrum's Law caveats template

In `design.md`, the Hyrum's Law section names what is contractually guaranteed and what is observable but explicitly unsupported. This is critical context for future skills (especially `code-write` for the implementation behind the contract — it tells the implementer what they can change later vs what they must preserve).

```markdown
## Hyrum's Law caveats
### Guaranteed (the contract)
- The fields named in `components/schemas/Order` and their types.
- The HTTP status codes documented in each path's `responses` block.
- The error code values in `ErrorResponse.code`.

### Observable but unsupported
- The exact text in `ErrorResponse.message` (only `code` is contract; message is human-friendly).
- The order of items in `Order.items` array (sorted by line item ID today; do not rely).
- Response time SLAs (informally targeted but not part of the contract; SLA is documented separately).
- The exact set of HTTP headers (we may add headers; clients must not rely on absence of any specific header).
```

## Rules

1. Never write outside `.temp/task-<slug>/` until the user signs off (then the artifact may move to the working tree).
2. `.temp/` is in `.gitignore`.
3. Do not auto-clean.
4. Slug preserved across the session.
5. The contract artifact is the deliverable; everything else is rationale around it. Without the artifact, the design is incomplete.
6. If the artifact lives in the working tree, the validator confirms the diff; if under `.temp/`, the report recommends where to land it.

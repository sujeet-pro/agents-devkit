# `code-refactor` — artifact format

## `.temp/task-<slug>/` layout

```
.temp/task-<slug>/
├── prompt.txt                                 # verbatim user prompt + ISO timestamp
├── plan.md                                    # Phase 3 — move + micro-step sequence
├── (optional) skill-plan.md                   # if called from /adk-core:auto
├── validation/
│   └── per-skill/
│       └── code-refactor.md                   # per-step validation evidence
└── report.md                                  # Phase 6 — final report
```

## Slug rules

1. Kebab-case. Often shaped `<verb>-<area>` (e.g. `extract-cart-validation`, `rename-getcwd`, `dedupe-date-parsers`, `split-checkout-index`, `inline-fetcher`, `move-utils`).
2. 3-6 words.
3. Date-prefix only when needed for disambiguation.
4. Generated by `bin/adk-task-slug`.

## Required artifacts

- **`plan.md` with `## Micro-steps`** — without a numbered step list, the green-between-steps invariant cannot be tracked.
- **`validation/per-skill/code-refactor.md`** with per-step evidence (the suite output after each step).
- **`report.md` with `## Micro-steps` table** showing the suite size after each step (verifying the green-between-steps invariant).

## Per-step validation log shape

`validation/per-skill/code-refactor.md`:

```markdown
## Validator

### Baseline (Phase 1)
- typecheck: exit 0
- lint: exit 0
- test (full affected package): exit 0, 187 passed

### Step 1 — <description>
- <test command>: exit 0, 187 passed
- (if relevant) typecheck after this step: exit 0

### Step 2 — <description>
- <test command>: exit 0, 187 passed

### Step 3 — <description>
- <test command>: exit 0, 187 passed

### Final (Phase 5)
- typecheck: exit 0
- lint: exit 0
- test (full): exit 0, 187 passed (same count as baseline)
- snapshot tests: no --update needed (verified)
```

## Cross-skill compatibility

- When `code-refactor` is followed by `/adk-review:review-code-changes`, the review skill reads `report.md` and `validation/per-skill/code-refactor.md` to verify the green-between-steps invariant in the diff.
- When `code-refactor` is part of a chain (rare — typically `code-refactor` is its own self-contained task), other skills do not write to its `code-refactor.md` log file.

## Rules

1. Never write outside `.temp/task-<slug>/` until the user signs off.
2. `.temp/` is in `.gitignore`.
3. Do not auto-clean.
4. The slug is preserved across skill invocations within a session.
5. The validation log is append-only — each step adds a section; never overwrite.
6. The suite count post-step (e.g. "187 passed") is a quick at-a-glance proof of behavior preservation. If the count changes step-to-step, that's a flag (a step removed or added a test, which is suspect for a refactor).

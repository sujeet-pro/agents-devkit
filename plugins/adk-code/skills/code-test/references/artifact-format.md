# `code-test` — artifact format

## `.temp/task-<slug>/` layout

```
.temp/task-<slug>/
├── prompt.txt                                 # verbatim user prompt + ISO timestamp
├── behaviors.md                               # Phase 3 — behavior list + trio per behavior
├── (optional) skill-plan.md                   # if called from /adk-core:auto
├── validation/
│   └── per-skill/
│       └── code-test.md                       # test-engineer hand-off + fail-first evidence + coverage delta
└── report.md                                  # Phase 6 — final report
```

The new test FILES live in the working tree (in the repo) — that's the deliverable. `behaviors.md` and `validation/per-skill/code-test.md` are working artifacts; `report.md` is the deliverable summary.

## Slug rules

1. Kebab-case. Often shaped `test-<area>` or `cover-<area>` (e.g. `test-order-state-machine`, `cover-discount-calculator`, `e2e-checkout-flow`).
2. 3-6 words.
3. Date-prefix only for disambiguation.
4. Generated by `bin/adk-task-slug`.

## Required artifacts

- **`behaviors.md` with the trio per behavior** — proves you enumerated behaviors before authoring.
- **`validation/per-skill/code-test.md` with fail-first evidence per test** — proves the tests are real (red→green transition observed).

If either is missing at Phase 6, the validator fails.

## Per-test fail-first evidence shape

`validation/per-skill/code-test.md`:

```markdown
## Test-engineer hand-off — <ISO timestamp>

### Behavior B1 — Expired codes are rejected

#### Test 1 — happy: future-expiry code → applied
- File: services/checkout/discount.test.ts
- Test name: "applies a code with future expiry"
- Fail-first transition:
  - Mutation: commented out the `isExpired(code)` check (line 47).
  - Run: `pnpm test -- discount.test.ts`. Exit 1. Test failed: expected $40, received $50.
  - Restore.
  - Run: `pnpm test -- discount.test.ts`. Exit 0. Test passed.

#### Test 2 — boundary: same-day expiry, before midnight → applied
- File: services/checkout/discount.test.ts
- Test name: "applies same-day codes until midnight"
- Fail-first transition: …

#### Test 3 — error: expired yesterday → not applied
…

### Behavior B2 — Single-use codes apply once
…

## Coverage delta (if --coverage)
- pnpm test --coverage --filter checkout-api
- Lines: 50% (before) → 88% (after) on discount.ts
- Branches: 35% → 79%
- Per-line gaps remaining: lines 92, 105, 117 (error handling for upstream API)
```

## Cross-skill compatibility

- When `code-test` is followed by `/adk-review:review-code-changes`, the review skill reads `report.md` + `behaviors.md` + `validation/per-skill/code-test.md`. The reviewer verifies fail-first evidence is present per test.
- When `code-test` is a prerequisite to `code-refactor` (establishing safety net), the slug from `code-test` is reused; `code-refactor` runs as a follow-on task in the same `.temp/task-<slug>/` (rare; usually they're separate slugs).
- `code-test` does NOT chain with `code-bugfix` — `code-bugfix` adds the regression test as part of the fix.
- `code-test` does NOT chain with `code-write` — `code-write` adds tests for new behavior via the test-engineer subagent.

## Rules

1. Never write outside `.temp/task-<slug>/` until the user signs off (then the test files are in the working tree, not under `.temp/`).
2. `.temp/` is in `.gitignore`.
3. Do not auto-clean.
4. The slug is preserved across the session.
5. The fail-first evidence is per-test; not per-behavior. Each new test must have a recorded red→green transition.

## When the new tests are 50+

For a large coverage backfill, the per-test fail-first evidence list can be long. Convention:

- Group by behavior in the validation log; per behavior, document fail-first ONCE if all tests in the trio share the same mutation pattern (e.g. "commented out the entire validation function; all 3 tests went red; restored; all 3 green").
- Per-test evidence is required when each test exercises a different code path.

Use judgment; the goal is "the reviewer can verify the tests are real" — not "every test has 4 lines of identical mutation prose".

# `code-bugfix` — artifact format

## `.temp/task-<slug>/` layout

```
.temp/task-<slug>/
├── prompt.txt                                 # verbatim user prompt + ISO timestamp + any pasted stack trace
├── reproducer.md                              # Phase 2 — the failing test + observed output
├── plan.md                                    # Phase 3 — root cause + patch plan
├── (optional) skill-plan.md                   # if called from /adk-core:auto
├── (optional) context.md                      # if /adk-core:auto ran context-gather
├── validation/
│   └── per-skill/
│       └── code-bugfix.md                     # implementer + test-engineer hand-offs + validation logs
└── report.md                                  # Phase 6 — final report
```

## Slug rules

1. Kebab-case. Often shaped `fix-<symptom>-<area>` or `<area>-<symptom>`.
2. 3-6 words from the prompt's nouns/verbs.
3. Date-prefixed only if the slug already exists in `.temp/`.
4. Generated by `bin/adk-task-slug "<prompt>"`.
5. Preserved across the session.

## Required artifacts (cannot skip even under `--auto`)

- **`reproducer.md`** — without this, the fix is unverified.
- **`plan.md` with `## Root cause` heading** — without this, the diagnosis is missing.
- **`validation/per-skill/code-bugfix.md`** with the red→green transition for the regression test.

If any of these is missing at Phase 6, the validator fails and the skill does NOT mark itself "done".

## Test file location

The regression test lives where the repo's conventions say it lives — beside the source (`*.test.ts`), in `tests/` (`test_*.py`), in `__tests__/` (Jest convention), in `src/test/kotlin/` (Gradle), etc.

`.temp/task-<slug>/reproducer.md` references the in-repo test file path; the test code lives in the repo, not in `.temp/`.

## Cross-skill compatibility

- When `code-bugfix` is called after `/adk-investigate:investigate-incident`, the incident's hypothesis is read from `.temp/task-<slug>/investigation/incident.md` as a starting point. `code-bugfix` still writes its own `reproducer.md` and `plan.md` — the incident skill provides direction; `code-bugfix` provides verification.
- When `code-bugfix` is followed by `/adk-review:review-code-changes`, the review skill reads `report.md` and `validation/per-skill/code-bugfix.md`.

## What goes where

| Artifact | File |
| --- | --- |
| Verbatim prompt + stack trace | `prompt.txt` |
| Reproducer (failing test + output) | `reproducer.md` |
| Root cause + patch plan | `plan.md` |
| Per-file changes + commands run | `validation/per-skill/code-bugfix.md` (implementer hand-off) |
| Regression test fail-first evidence | `validation/per-skill/code-bugfix.md` (test-engineer hand-off) |
| Final report | `report.md` |

## Rules

1. Never write outside `.temp/task-<slug>/` until the user signs off (then the change moves to the working tree).
2. `.temp/` is in `.gitignore`. Verify before any write.
3. The folder is durable context — do not auto-clean.
4. The slug is preserved across skill invocations within a session.
5. The reproducer test in the repo IS in the working tree — that's the point. It will be reviewed and committed.

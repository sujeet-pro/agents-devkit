# `code-perf` — artifact format

## `.temp/task-<slug>/` layout

```
.temp/task-<slug>/
├── prompt.txt                                 # verbatim user prompt + ISO timestamp
├── measurement-baseline.md                    # Phase 2 — captured baseline
├── bottleneck.md                              # Phase 3 — identification with quoted evidence
├── plan.md                                    # Phase 4 — fix plan
├── measurement-after.md                       # Phase 5 — post-fix re-measurement
├── (optional) flame-graph.svg                 # if profile-based diagnosis
├── (optional) heap-snapshot-baseline.heapsnapshot
├── (optional) heap-snapshot-after.heapsnapshot
├── (optional) lighthouse-baseline.json
├── (optional) lighthouse-after.json
├── (optional) skill-plan.md                   # if called from /adk-core:auto
├── validation/
│   └── per-skill/
│       └── code-perf.md                       # implementer + measurement evidence
└── report.md                                  # Phase 7 — final report
```

## Slug rules

1. Kebab-case. Often shaped `perf-<area>-<symptom>` (e.g. `perf-checkout-p99-spike`, `perf-doc-processor-memory-leak`, `perf-dashboard-lcp`, `perf-ci-build`).
2. 3-6 words.
3. Date-prefix only for disambiguation.
4. Generated by `bin/adk-task-slug`.

## Required artifacts (cannot skip even under `--auto`)

- **`measurement-baseline.md`** — proves the baseline was captured BEFORE editing.
- **`bottleneck.md`** with quoted evidence (≤15 words per quote).
- **`measurement-after.md`** — proves re-measurement was done.
- **`report.md`** with the before/after table.

If any is missing at Phase 7, the validator fails.

## Profile / heap / Lighthouse attachments

When the diagnosis uses a tool that produces a binary or large file:

- Save to `.temp/task-<slug>/<artifact-name>`.
- Reference from `bottleneck.md` and `measurement-baseline.md` / `measurement-after.md`.
- Don't embed the raw binary in the markdown; just link.

Examples:

- Chrome DevTools perf trace: save the JSON via "Save profile" → `.temp/task-<slug>/profile-baseline.json`.
- V8 heap snapshot: `.temp/task-<slug>/heap-baseline.heapsnapshot`.
- Lighthouse JSON output: `.temp/task-<slug>/lighthouse-baseline.json`.
- Datadog flame graph: take a screenshot OR copy the trace ID; the trace lives in DD.

## Cross-skill compatibility

- When `code-perf` is preceded by `/adk-investigate:investigate-datadog`, the investigation's findings are at `.temp/task-<slug>/investigation/datadog.md` and `code-perf` reads them as starting context.
- When `code-perf` is followed by `/adk-review:review-code-changes`, the review skill reads `report.md` + `bottleneck.md` + `measurement-after.md`.

## Rules

1. Never write outside `.temp/task-<slug>/`.
2. `.temp/` is in `.gitignore`.
3. Do not auto-clean.
4. Slug preserved across the session.
5. Every measurement file (baseline + after) must use the SAME protocol — that's the point of "re-measure".
6. Quoted evidence is ≤15 words per quote; multiple quotes allowed if the bottleneck has multi-cause evidence.

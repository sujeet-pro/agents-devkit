# `code-migrate` — artifact format

## `.temp/task-<slug>/` layout

```
.temp/task-<slug>/
├── prompt.txt                                 # verbatim user prompt + ISO timestamp
├── migration-notes.md                         # Phase 2 — curated quotes from upstream guide
├── migration-inventory.md                     # Phase 3 — per-rule call-site count + samples
├── plan.md                                    # Phase 4 — group sequence + validation plan
├── (optional) skill-plan.md                   # if called from /adk-core:auto
├── validation/
│   └── per-skill/
│       └── code-migrate.md                    # per-group validation evidence
└── report.md                                  # Phase 7 — final report
```

## Slug rules

1. Kebab-case. Often shaped `migrate-<tool>-<from>-to-<to>` (e.g. `migrate-react-18-19`, `migrate-jest-to-vitest`, `migrate-spring-boot-2-3`, `migrate-node-18-20`).
2. 4-7 words.
3. Date-prefix only if needed for disambiguation.
4. Generated by `bin/adk-task-slug`.

## Required artifacts (cannot skip even under `--auto`)

- **`migration-notes.md`** — proves the upstream guide was read.
- **`migration-inventory.md`** — proves the call-sites were enumerated before editing.
- **`plan.md` with `## Groups` table** — proves the changes were grouped intentionally.
- **`validation/per-skill/code-migrate.md` with per-group sections** — proves per-group validation ran.

If any of these is missing at Phase 7, the validator fails and the skill does NOT mark itself "done".

## Per-group validation log shape

`validation/per-skill/code-migrate.md`:

```markdown
## Validator

### Baseline (Phase 1)
- typecheck: exit 0
- lint: exit 0
- test (full affected package): exit 0, 1247 passed
- build: exit 0

### Group 1 — <name>
- typecheck: exit 0
- test (scoped): exit 0, 142 passed
- Files changed: src/.../Foo.tsx, src/.../Bar.tsx, …

### Group 2 — <name>
…

### Final (Phase 6)
- build: exit 0
- test (full): exit 0, 1247 passed (matches baseline)
- typecheck: exit 0
- lint: exit 0
- smoke check: <command> exit 0, <observed output>
```

## Cross-skill compatibility

- When `code-migrate` is followed by `/adk-review:review-code-changes`, the review skill reads `report.md` + `migration-notes.md` + `validation/per-skill/code-migrate.md`. The reviewer specifically looks for:
    - Each migration-guide rule applied appears in the diff.
    - Each "NOT applied" rule has a documented reason.
    - Per-group validation evidence is present.
- Migration tasks are typically not chained with other code-* skills (they're large enough to stand alone). Occasionally `code-migrate` is followed by `code-test` to backfill coverage on areas the migration touched.

## Rules

1. Never write outside `.temp/task-<slug>/` until the user signs off.
2. `.temp/` is in `.gitignore`.
3. Do not auto-clean.
4. The slug is preserved across the session.
5. The validation log is append-only — each group adds a section.
6. The migration-notes.md must include the source URL and fetch timestamp so the reviewer can verify against the same authority.

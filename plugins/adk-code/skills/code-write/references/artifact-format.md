# `code-write` — artifact format

## `.temp/task-<slug>/` layout

Enforced by `/adk-core:temp-folder`. `code-write` produces:

```
.temp/task-<slug>/
├── prompt.txt                                # verbatim user prompt + ISO timestamp
├── plan.md                                   # Phase 3 output
├── (optional) skill-plan.md                  # if called from /adk-core:auto
├── (optional) context.md                     # if /adk-core:auto ran context-gather
├── validation/
│   └── per-skill/
│       └── code-write.md                     # implementer + test-engineer hand-offs
└── report.md                                 # Phase 6 output
```

## Slug rules

1. Kebab-case (`add-since-flag-export`, not `addSinceFlagExport` or `add_since_flag_export`).
2. 3-6 words from the prompt's nouns and verbs.
3. Date-prefixed (`2026-05-03_add-since-flag-export`) only when the same slug already exists in `.temp/`.
4. Generated by `bin/adk-task-slug "<prompt>"` (from `adk-core`).
5. Preserved across the session: if `code-write` is the second skill in a chain (`auto → code-write → review-code-changes`), the slug from `auto` is reused.

## Rules

1. Never write outside `.temp/task-<slug>/` until the user signs off (then the change moves to the working tree, not somewhere else under `.temp/`).
2. `.temp/` is in `.gitignore`. Verify before any write — if a parent has no `.gitignore` entry, surface it.
3. The folder is durable context — do not auto-clean after task completion. The operator prunes manually.
4. The slug is preserved across skill invocations within a session.
5. Validation logs go in `validation/per-skill/code-write.md`, not at the root, so chained skills can write their own log without collision.
6. Both the implementer and test-engineer subagents append to the SAME `code-write.md` so the per-skill log is a single readable artifact.

## Cross-skill compatibility

When `code-write` is part of a chain that also includes `code-test` (rare — usually `code-write` adds tests itself), both skills write to `validation/per-skill/<their-name>.md` so logs do not collide.

When `code-write` is followed by `/adk-review:review-code-changes`, the review skill reads `report.md` and `validation/per-skill/code-write.md` to know what to review.

## What goes where

| Artifact | File |
| --- | --- |
| Verbatim prompt | `prompt.txt` |
| Plan (files touched, approach) | `plan.md` |
| Implementer's per-file change log + commands | `validation/per-skill/code-write.md` |
| Test-engineer's coverage delta + fail-first evidence | (appended to) `validation/per-skill/code-write.md` |
| Final report | `report.md` |
| (if any) subagent dispatch summary | `dispatch.md` (managed by `/adk-core:auto`, not `code-write`) |
| Reference repos cloned for research | `.temp/reference-repos/<owner>__<repo>/` (not under task slug) |
| Notes scribbled mid-flow | `.temp/notes/<slug>.md` (not under task slug) |

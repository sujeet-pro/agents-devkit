# `docs-changelog` — per-phase validator

Logged to `.temp/task-<slug>/validation/docs-changelog.md`.

## Phase 0

- [ ] `.temp/task-<slug>/` exists, gitignored.
- [ ] Prompt saved verbatim.
- [ ] `CHANGELOG.md` path resolved (or flagged missing).

## Phase 1

- [ ] `bin/adk-info --check` == 0.
- [ ] `git rev-parse <from-tag>` and `<to-tag>` both succeed.
- [ ] Style detected (`kaC` | `semantic` | `free`) with confidence
      and evidence lines in `detected-style.txt`.
- [ ] Existing release-header pattern captured for mirroring.

## Phase 2

- [ ] `commits.txt` captured; count of commits recorded.
- [ ] If count == 0, stop with a clear message (no commits in range).
- [ ] `classified.md` has one row per commit.
- [ ] Every row has a group; breaking-change flag explicit.
- [ ] No commit is double-counted across groups.

## Phase 3

- [ ] `changelog-entry.md` exists.
- [ ] Header line matches existing release-header pattern.
- [ ] If any breaking changes: "Breaking changes" section is first,
      per `references/breaking-change-callout.md`.
- [ ] Each entry is one sentence, imperative-mood initial verb, no
      trailing period inside bullets is OK but consistent with
      existing file.
- [ ] Every entry traces to a commit in `classified.md` (no invented
      items).
- [ ] Every PR reference resolves (basic URL shape check).

## Phase 4 (under `--fix`)

- [ ] Insertion point identified (before previous version block,
      after any "Unreleased" section).
- [ ] `backup/CHANGELOG.md` exists.
- [ ] Post-write: the only byte-level changes between backup and
      current `CHANGELOG.md` are an inserted block at the insertion
      point (no drift elsewhere).
- [ ] If the target version block already existed: user opt-in
      recorded.
- [ ] `git add CHANGELOG.md` succeeded.
- [ ] No `git commit` / `git push` was called.

## Content guardrails

- [ ] No "generated by" / "AI-authored" footer.
- [ ] No raw secret patterns.
- [ ] No entries > 200 chars (probably a commit-body dump).
- [ ] Entries don't start with a type prefix (`feat(...):`) —
      that's a commit subject, not a user-facing line.

## On failure

- Log + block next phase.
- After 3 same-kind failures, stop and surface.

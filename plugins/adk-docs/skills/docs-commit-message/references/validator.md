# `docs-commit-message` — per-phase validator

Logged to `.temp/task-<slug>/validation/docs-commit-message.md`.

## Phase 0

- [ ] `.temp/task-<slug>/` exists, gitignored.
- [ ] Prompt saved verbatim.
- [ ] `git rev-parse HEAD` succeeded OR (fresh repo) this is the
      first commit.

## Phase 1

- [ ] `git diff --cached --stat` produced non-empty output.
- [ ] `staged.diff` exists and is non-empty.
- [ ] `recent-subjects.txt` captured.
- [ ] `detected-style.txt` has one of `conv`, `semantic`, `free`.
- [ ] If `--style` was passed, it overrides detection; override
      recorded.

## Phase 2 — draft

- [ ] `commit-msg.txt` exists.
- [ ] First non-blank line (subject) length ≤ 72.
- [ ] Subject does not end in a period.
- [ ] Subject starts with imperative mood (first word is a bare
      verb — `add`, `fix`, `migrate`, etc. — not `added` / `adding`).
- [ ] Exactly one blank line between subject and body.
- [ ] No paragraph in the body exceeds 72 chars wide (URLs and
      lines inside code fences excepted).
- [ ] Trailers (if any) appear after a single blank line following
      the body.

## Phase 3 — style-specific

- [ ] If `style=conv`: subject matches
      `^(feat|fix|chore|refactor|docs|test|perf|build|ci|style|revert)(\([^)]+\))?(!)?: .+`.
- [ ] If `style=semantic`: same as conv + `BREAKING CHANGE:` footer
      if any breaking change is indicated.
- [ ] If `style=free`: subject mirrors the casing and structure of
      the majority in `recent-subjects.txt`.

## Phase 4 — pre-commit (under `--fix`)

- [ ] User confirmed the ask (one explicit confirmation, even under
      `--auto`).
- [ ] Staging hash stable (no drift between Phase 1 and Phase 4).
- [ ] `git commit --file commit-msg.txt` ran without `--amend`,
      `-a`, `--no-verify`.
- [ ] Captured the resulting SHA + `git show --stat HEAD`.
- [ ] If commit-msg / pre-commit hook rejected: rejection captured,
      NO retry with `--no-verify`.

## Content guardrails (all phases)

- [ ] No "generated by" / "AI-authored" footer.
- [ ] No ticket ref in trailers that isn't present in the diff /
      branch name / repo ticket-ref pattern.
- [ ] No `--no-verify` / `--amend` hint in the message.
- [ ] No raw secret patterns (basic regex: AWS keys, GitHub tokens,
      Slack tokens). Stop and warn if matched.

## On any failure

- Log to `validation/docs-commit-message.md`.
- Block next phase.
- 3 same-kind failures → stop and surface.

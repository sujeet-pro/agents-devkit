# Skill Anatomy

A **skill** is a single specialist playbook. `build-feature` is the playbook for implementing code. `review-pr` is the playbook for reviewing a PR. `docs-write` is the playbook for authoring docs. Every skill follows the same shape so a coding agent can switch between them without relearning anything.

## Directory layout

A skill lives at `skills/<name>/` and contains:

```
skills/<name>/
├── SKILL.md                                    # entry point: frontmatter + thin orchestrator + managed references block
└── references/                                 # FLAT — no subdirectories, no _shared/
    ├── how-it-works.md                         # mermaid diagram + decision flow
    ├── workflow.md                             # task-specific phase expansion
    ├── modes.md                                # which --mode this skill supports
    ├── interaction-contract.md                 # PHYSICAL COPY synced from bin/canonical/
    ├── <name>-persona.md                       # the agent persona that drives this skill
    ├── <name>-output-format.md                 # response shape and severity rules
    ├── <name>-clarifying-questions.md          # default-ask questions + how-to-pick rubrics
    ├── <name>-validator.md                     # four-phase validator gate
    ├── <name>-anti-patterns.md                 # what to avoid
    └── <name>-examples.md                      # sample triggers and report shape
```

This is the contract:

- Directory name matches the SKILL.md frontmatter `name`.
- Skill folder names are **bare** — no `adk-` prefix on disk.
- The Claude Code plugin host invokes them as `/adk:<name>`.
- Each skill stays usable when copied out of this repository.
- `references/` is **flat**. No subdirectories, no `_shared/`, no cross-skill references by relative path.
- Every reference file is **owned by this skill** — a copy, not a symlink.
- `references/interaction-contract.md` is a physical copy synced from `bin/canonical/interaction-contract.md` by `npm run sync-contracts`.

> [!NOTE]
> Migrated skills keep their existing `<task>-prefixed` reference filenames (e.g. `build-feature-persona.md`, `plan-brainstorm-validator.md`) to minimize churn. New skills use bare names (`persona.md`, `validator.md`).

## SKILL.md frontmatter

Spec-compliant for the [Claude Code skills spec](https://code.claude.com/docs/en/skills#frontmatter-reference). The repo also recognizes ADK-specific keys under `metadata`:

```yaml
---
name: build-feature                       # required, must equal folder basename (no `adk-` prefix)
description: |                            # required, single paragraph; Claude uses it for auto-invoke
  <when to use, what it does, when NOT to use>
metadata:                                 # optional, ADK-specific
  category: meta | discovery | plan | frontend | build | review | docs | audit | publish | observability | bootstrap
  kind: top | router | task
  modes: [auto, fix, review]
  layer: 0..10
  needs_mcp: [github, datadog, ...]
disable-model-invocation: false
---
```

Field rules:

- `name` and `description` drive activation. The description is the trigger sentence the harness matches against user intent.
- `description` ≤ 1024 characters.
- The body is ≤ 500 lines (soft cap; warning only).
- Cross-skill references use the dual form on first mention: `` `@adk:plan-brainstorm` (a.k.a. `adk-plan-brainstorm`) `` (per `bin/canonical/system-prompt.md`).

## Managed references block

The bottom of each `SKILL.md` carries a managed block listing every file shipped in `references/`. Generated by `bin/internal/manifest.mjs`:

```
<!-- adk:references:start -->

## References shipped with this skill

These files live in `references/` next to this `SKILL.md`. Read them when the skill activates; they are inlined here so the skill is fully self-contained (no cross-skill or shared sources).

| File | Purpose |
| --- | --- |
| `references/build-feature-persona.md` | The agent persona that drives this skill. |
| `references/build-feature-workflow.md` | Step-by-step protocol for this skill. |
| `references/build-feature-output-format.md` | Response shape and severity rules. |
| `references/interaction-contract.md` | Default-ask, explained-options, --auto contract every skill must follow. |
| ... |

<!-- adk:references:end -->
```

Everything else in `SKILL.md` is hand-authored.

## No shared guidance

There is no `ai-guidelines/`, no `references/_shared/`, no auto-propagation script for ADK content. If you change `references/<skill>-constitution.md` inside `build-feature`, that change does not propagate to `build-refactor`. This is the explicit trade-off:

- **Pro:** Each skill folder can be copied out into any other agent setup and works as-is.
- **Pro:** No "I edited the canonical file but forgot to refresh" bugs.
- **Con:** The same content lives in many places; a change with broad intent must be edited in every relevant skill by hand.

The one exception is `bin/canonical/interaction-contract.md` and `bin/canonical/system-prompt.md`, which are propagated byte-identically into every skill via `bin/adk-sync-contracts`. Per-skill copies of `references/interaction-contract.md` are derived — never edit them directly.

## Skill kinds

| Kind | Examples | What goes in the body |
| --- | --- | --- |
| Top router | `adk` | Intent table; routes to one of the 8 categories |
| Category router | `plan`, `build`, `review`, `docs`, `audit`, `publish`, `frontend`, `visualize` | Task-selection table; routes to a task skill |
| Task skill | `plan-brainstorm`, `build-feature`, `review-pr`, … | The actual workflow + output format + examples |
| Standalone task | `auto`, `requirements`, `scoping`, `setup`, `markdown`, `temp-folder`, `mode-contract`, `adopt-ai-in-repo`, `personal-skill-create` | Task skills that don't sit under a category router |

Routers ship a minimal `references/` (constitution, anti-patterns). Task skills ship the full vocabulary that applies to them.

## Validation

Run `npm run validate` to check structure across all 69 skills (counted by `bin/internal/manifest.mjs`). It enforces:

- Spec-compliant frontmatter only.
- Frontmatter `name` matches folder basename.
- Description ≤ 1024 chars.
- `references/` is flat (no subdirs, no `_shared/`).
- Any `references/<file>` cited inline in `SKILL.md` exists in the same folder.
- Generates / refreshes `skills-manifest.json`.

`npm run validate:sync` checks that every skill's `references/interaction-contract.md` is byte-identical to `bin/canonical/interaction-contract.md`.
